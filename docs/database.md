# Database

PostgreSQL 16 with Drizzle ORM. Schema source: `apps/api/src/database/schema/`.
Migrations: `apps/api/src/database/migrations/` (generated by `drizzle-kit`,
reviewed and committed; custom SQL migrations are allowed - see `0001`).

## Conventions

- Primary keys: `uuid` (`gen_random_uuid()`), except `audit_logs.id` (`bigserial`)
  for cheap ordered export.
- `created_at` / `updated_at` are `timestamptz`; business dates (Phase 2+) use
  `date` columns and are named explicitly (`transaction_date`, `posting_date`,
  `document_date`, `due_date`).
- Money (Phase 2+): `NUMERIC(19,4)`; rates `NUMERIC(19,8)`.
- Enumerations are PostgreSQL enums generated from the shared constants in
  `@accounting/types` so the database and TypeScript never drift.
- Every tenant-owned table carries `organization_id` or `company_id`; queries
  always filter by it.
- Constraints live in the database: NOT NULL, UNIQUE (including
  `NULLS NOT DISTINCT` for scoped uniqueness), CHECK, FOREIGN KEY with explicit
  `ON DELETE` behaviour (`restrict` for anything with history).
- Nothing financial is physically deleted. Master data is deactivated
  (`status = INACTIVE`).

## Phase 2 tables (accounting core)

| Table                | Purpose                                                          | Notable constraints                                                                                  |
| -------------------- | ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `accounts`           | Chart of accounts (hierarchy via `parent_id`)                    | `(company_id, code)` unique; `is_header`, `is_system`; enum type/subtype/normal balance              |
| `account_mappings`   | Configurable account roles (retained earnings, control accounts) | `(company_id, key)` unique; FK to postable accounts                                                  |
| `fiscal_years`       | Fiscal calendar per company                                      | unique name and start per company; `end_date > start_date`                                           |
| `fiscal_periods`     | 12 monthly periods per year, OPEN/CLOSED                         | `(fiscal_year_id, period_number)` unique; number 1-13                                                |
| `document_sequences` | Numbering per company/type/year                                  | unique triple; atomic upsert increments                                                              |
| `journal_entries`    | Accounting documents (status, dates, totals, workflow actors)    | unique document number, idempotency key and source per company; posted rows must be balanced (CHECK) |

Money columns are `NUMERIC(19,4)` (`money()` helper in `schema/accounting.ts`); business dates are `date` columns.

## Phase 3 tables (AR / AP subledgers)

## Hardening phase 1 (accounting controls)

`fiscal_periods.status` gains `SOFT_CLOSED` and `LOCKED`, plus `reopen_reason`,
`locked_at`, `locked_by`; `journal_entries.correction_of_id` links a correcting
entry to the original it replaces. Migration `0011_accounting_controls.sql` also
installs `journal_entries_guard_locked_period()`: no row may enter a ledger
status while its period is `LOCKED`, whatever client writes it.

## Posted-journal immutability

Migration `0003_posted_journal_immutability.sql` installs triggers that reject
any UPDATE of financial columns, any status change back to an unposted state,
DELETE of posted entries, and INSERT/UPDATE/DELETE of their lines. Covered by
`apps/api/test/accounting.e2e-spec.ts`.

## Audit immutability

Migration `0001_audit_log_immutability.sql` installs
`audit_logs_reject_mutation()` and triggers `BEFORE UPDATE OR DELETE` (row) and
`BEFORE TRUNCATE` (statement). This holds for every database role, including
the application user, and is covered by the e2e test
`keeps the audit trail append-only even for direct SQL`.

## Workflow

```bash
pnpm db:generate       # drizzle-kit generate  (after editing schema/*.ts)
pnpm db:migrate        # apply pending migrations to DATABASE_URL
pnpm db:seed           # idempotent development seed
pnpm db:reset          # DROP schema + migrate + seed (development only)
pnpm --filter @accounting/api db:generate -- --custom --name <name>   # hand-written SQL migration
```

Integration tests use `TEST_DATABASE_URL` (`accounting_test`, created by
`infrastructure/docker/postgres/init/01-test-database.sql`) and rebuild the
schema on every run.
